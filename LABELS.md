# Issue Labels

This document describes the labels used in this repository for contribution workflows.

## Contribution Type Labels

- **good first issue**: Issues suitable for new contributors. These are well-scoped, have clear acceptance criteria, and include implementation guidance.
- **help wanted**: Issues that need community help but may require more experience.
- **bug**: Reports of defects or unexpected behavior.
- **feature**: Requests for new functionality.
- **enhancement**: Improvements to existing functionality.
- **documentation**: Issues related to documentation, examples, or guides.

## Priority Labels

- **priority: low**: Nice to have, but not urgent.
- **priority: medium**: Important but can be scheduled.
- **priority: high**: Urgent, should be addressed soon.

## Component Labels

- **sdk**: Issues related to the SDK client and core functionality.
- **types**: Issues related to TypeScript type definitions.
- **tests**: Issues related to test coverage or test infrastructure.
- **examples**: Issues related to example code or usage documentation.

## Status Labels

- **status: blocked**: Issue is blocked by another issue or external dependency.
- **status: in progress**: Issue is currently being worked on.
- **status: ready for review**: PR is ready for maintainer review.
- **status: needs info**: More information is needed to proceed.


## Label Usage Guidelines

- Use **good first issue** for tasks that can be completed in 1-4 hours by a new contributor
- Use **help wanted** for tasks that may require more experience or domain knowledge
- Always include a priority label for issues and PRs
- Use component labels to help contributors find relevant issues
- Campaign-ready issues should have detailed descriptions and acceptance criteria
